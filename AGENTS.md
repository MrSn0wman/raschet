# Правила проекта «Расчёт.net» (для агентов)

## Процесс

1. **После КАЖДОГО изменения — проверка в браузере субагентом.** Ни один коммит не уходит без живого прогона: headless Chrome (C:\Program Files\Google\Chrome\Application\chrome.exe), страница поднимается через `python -m http.server`, проверяются рендер, отсутствие JS-ошибок и затронутое поведение. Дизайн-изменения — ещё и скриншоты 320/1280, обе темы.
2. **Конвейер сборки:** `python -B _build/build/build_all.py --test` собирает самостоятельный `_build/out` из версионированных `_build/sources/pages/*/{shell.html,head.html,body.html,scripts.html,page.css}` и общих `_build/parts/`, затем запускает CSP/SEO/privacy-рекламу/PWA и строгий `test_site.py` на том же OUT. Соседний raschet-old и сеть не нужны. Page-specific правки делайте в sources, общие — в parts; готовые публичные HTML не являются единственным источником. После PASS и независимого review используйте `scripts/publish_local_build.py --dry-run`, затем без dry-run для локальной синхронизации и повторите browser gate на корне. Никогда не очищайте корень: build разрешает замену только собственного отмеченного OUT.
3. **Публикация — только после явного разрешения владельца.** Сборка и локальная синхронизация ничего не commit/push-ят. Перед commit/push: review полного diff, чистая воспроизводимая сборка, независимый browser/security PASS, проверить пустой production `RASCHET_API_BASE` по самому имени константы, отсутствие секретов и синхронность sources/parts/готовых файлов. Не используйте `git checkout -- _build/parts/ui.js` для отвязки API: это уничтожает текущие изменения. Локальные конфигурации держите вне production-исходников. После разрешённого push проверьте живой https://raschet.net/ после сборки Pages.
4. **Дизайн** — субагент-критик по чек-листу `~/.dsh/design-critic.md` до PASS. **Код** — security-субагент по OWASP при изменениях логики/форм.
5. Числа с «₽» — с неразрывным пробелом (`\u00A0₽` в JS, `&nbsp;₽` в разметке). Случайность — только `crypto.getRandomValues` (см. `secureInt`/`secureIndex`). Пользовательский ввод — только через `textContent`/`esc()`, никакого innerHTML с ним.
