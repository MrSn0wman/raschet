# Расчёт.net — онлайн-калькуляторы и инструменты

Статический сайт на HTML/CSS/JavaScript: **73 инструмента, 79 полноценных страниц** (включая 404), 60 редиректов со старых адресов, 2 страницы подтверждения владения. Sitemap содержит 78 адресов без 404. Опубликованный сайт: https://raschet.net/.

## Исходники и готовые файлы

- [_build/sources/](_build/sources/): версионированные исходники каждой страницы. В pages/<slug> лежат shell.html, head.html, body.html, scripts.html и page.css; manifest.json задаёт страницы и редиректы.
- [_build/parts/](_build/parts/): общие стили, шапка, футер, интерфейс, ранняя privacy-политика и PWA-манифест.
- [_build/build/](_build/build/): самостоятельная сборка, обработка CSP/SEO/рекламы/PWA и строгие проверки. Старый raschet-old не нужен.
- [assets/](assets/): локальные шрифты, QR-библиотека, изображения, privacy/analytics.js и обновляемые курсы ЦБ.
- Готовые index.html и <slug>/index.html в корне нужны GitHub Pages. **Не правьте их как единственный источник:** правки страниц делайте в canonical sources, общие — в parts, затем пересобирайте и синхронизируйте.
- [backend/](backend/): необязательный FastAPI API для VPS. Сейчас RASCHET_API_BASE пустой: production-фронтенд не подключён к backend.

## Сборка и проверки

Сборке нужен Python 3.12+. Для браузерных проверок — Node.js 22+ (native WebSocket) и Chrome. Работайте из корня репозитория.

```bash
python -B _build/build/build_all.py --test
python -B _build/build/test_site.py --site _build/out --result /path/to/qa.json
node tests/test_calculators.js _build/out
python -B tests/build_pipeline.py
```

Первая команда создаёт отдельный _build/out и запускает весь конвейер на нём. Можно задать --site /path/to/dedicated-out. Сборка проверяет исходники **до** удаления прежнего OUT и заменяет только каталог с собственным маркером .raschet-build; корень репозитория, каталоги исходников и непомеченные каталоги не очищаются.

Сборка не требует сети, серверов старого сайта или копирования опубликованных HTML как источника. Генератор собирает страницы из частей и page-specific файлов, сохраняет метаданные, локальные ресурсы, CNAME и verification pages. Хэш PWA рассчитывается по итоговым публичным файлам без самого sw.js; повторная сборка тех же входов даёт тот же результат. API, адреса с query/hash и ответы private/no-store в SW не кэшируются.

Строгий test gate возвращает ненулевой код при пропущенной странице/записи, ошибках JavaScript, нарушениях инвентаря, ссылок, ресурсов или взаимодействий. Baseline необязателен и не заменяет проверки. В тестах внешние запросы блокируются; реальные письма и production API не используются. При нестандартной установке передайте test_site.py параметры --chrome и --node.

### Обновление готовых файлов локально

После успешной сборки и независимого browser/security review:

```bash
python -B scripts/publish_local_build.py --site _build/out --dry-run
python -B scripts/publish_local_build.py --site _build/out
python -B _build/build/test_site.py --site . --result /path/to/root-qa.json
```

Скрипт синхронизации проверяет сборку, обновляет только известные готовые веб-файлы и сохраняет остальные файлы. Он **не делает commit/push**, не удаляет неизвестные файлы и не меняет настройки хостинга. Публикация — отдельное действие после разрешения владельца, проверки diff и полного QA.

## Приватность и безопасность

[privacy-routes.json](_build/parts/privacy-routes.json) задаёт чувствительные маршруты: номера карт, ИНН/СНИЛС, пароли, QR, свободный текст/списки, имена участников долей и обратная связь. Сборка сверяет его с JS-политикой.

- Синхронный privacy.js исполняется до сторонних скриптов: очищает URL от query/hash, оставляя разрешённые параметры только в памяти для локального восстановления расчёта. Простые существующие якоря прокручиваются без возвращения hash в адрес.
- На чувствительных страницах sharing/restore ввода, аналитика и рекламные скрипты отключены. На остальных Метрика получает очищенный адрес; Webvisor, карты кликов и автоматическая отправка ссылок отключены.
- Начальный URL всё равно может попасть в журналы хостинга или к получателю ссылки. Не помещайте персональные данные в URL вручную. localStorage хранит тему и избранное, не введённые расчёты.
- Неверные значения очищают результат кредита/ипотеки/процентов и блокируют copy/share. Сроки проверяются до вычислений; случайные числа ограничены бюджетом и генерируются CSPRNG.
- Мета CSP не обеспечивает frame-ancestors. GitHub Pages без дополнительного прокси/CDN не позволяет выставить полноценный HTTP CSP/X-Frame-Options для статики. Это ограничение хостинга, а не исправление HTML; изменения внешних аккаунтов не выполняются автоматически.

## Backend, курсы и баннер

Настройка, TLS, лимиты запросов, права БД и сроки хранения описаны в [backend README](backend/README.md). Проверенный набор зависимостей — [requirements.lock](backend/requirements.lock); после установки запустите:

```bash
python -B -m unittest discover -s tests -p test_backend.py -v
```

SMTP проверяет сертификат и hostname; ASGI проверяет фактическое тело до JSON parser. Обращения в SQLite хранятся по настроенному сроку (30 дней по умолчанию). Логическое удаление не гарантирует стирание WAL, резервных копий или почты — их доступ и сроки настраиваются отдельно.

Курсы обновляет [workflow](.github/workflows/rates.yml) по официальным данным ЦБ; GitHub Actions закреплены по commit SHA. Не запускайте его вручную против production ради теста.

[Социальный баннер](assets/og-cover.png) обновлён до .net, 1200×630. Его необязательный генератор [generate_og_cover.py](scripts/generate_og_cover.py) требует Pillow и Cyrillic-capable TTF; обычная сборка копирует готовый PNG и не требует Pillow.
