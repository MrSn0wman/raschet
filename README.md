# Расчёт.рф — сайт-калькулятор

## Что было исправлено в этой версии

**1. Найден и исправлен реальный баг в JS.** Функции `formatMoney`/`formatMoney2`
были объявлены внутри обработчика `DOMContentLoaded`, а скрипты калькуляторов
вызывают их синхронно при загрузке страницы — то есть раньше, чем успевало
сработать это событие. Из-за этого в браузере при первой загрузке страницы
калькулятор должен был падать с `ReferenceError`. Исправлено: теперь эти функции
объявляются сразу, до `DOMContentLoaded`.

**2. Найдены и исправлены 7 SVG-иконок без `width`/`height`.** Иконки калькуляторов
на главной странице (ипотека, вклад, кредит, площадь, объём, проценты, ИМТ) не имели
явных размеров в самом SVG — размер задавался только через CSS. Если CSS почему-то
не подгружался, иконки растягивались на весь экран (это видно на присланных
скриншотах). Теперь у всех SVG на сайте прописаны явные `width`/`height`, плюс
добавлено защитное правило `svg{ max-width:100% }` — размер больше не может «уехать»,
даже если стили не применились.

**3. Сайт стал полностью самодостаточным.** Раньше CSS и JS подключались как отдельные
файлы (`assets/css/style.css`, `assets/js/*.js`). Если открыть сайт способом, который
отдаёт браузеру только один HTML-файл, а не всю папку целиком (именно это, похоже,
произошло на скриншотах — сайт открылся полностью без стилей), эти файлы просто не
находятся. Теперь CSS и JS встроены прямо в каждую HTML-страницу — она не зависит
ни от каких соседних файлов и будет выглядеть одинаково при любом способе открытия.

**4. На трёх страницах вообще не было подключено ни одного скрипта** (about.html,
privacy.html, advertising.html) — там не работали ни гамбургер-меню, ни выпадающие
списки в шапке. Добавлено.

## Как всё перепроверено

- Все 11 HTML-файлов повторно прошли валидацию разметки.
- Все внутренние ссылки проверены на существование целевого файла — битых нет.
- Проверено, что ни один файл больше не ссылается на `assets/css` или `assets/js`.
- Проверено, что у каждого SVG в разметке явно задан `width`.
- Запущена симуляция полной загрузки каждой из 7 калькуляторных страниц через
  минимальный DOM-эмулятор — **в реалистичном порядке**: сначала выполняются все
  встроенные `<script>` по очереди (как это делает браузер при парсинге HTML),
  и только затем срабатывает `DOMContentLoaded`. Именно этот более строгий тест
  и поймал баг с `formatMoney`, который более ранняя, упрощённая версия теста
  пропускала (раньше в тестовую песочницу функция подставлялась напрямую, минуя
  реальный код инициализации, поэтму тест 매 давал ложное «ОК»).

## Почему могли не открываться ссылки на телефоне

Судя по адресной строке на скриншотах, файл открывался через какое-то
приложение-посредник (не напрямую `file://` и не обычный HTTP-хостинг). Такие
инструменты часто отдают браузеру только тот файл, который вы открыли, — и не видят
остальные файлы рядом с ним. Даже с полностью встроенными CSS/JS переходы на другие
HTML-страницы (`calc-mortgage.html`, `calc-area.html` и т.д.) при таком способе
открытия могут не работать, потому что это уже вопрос не кода, а способа хостинга.

Самый надёжный вариант на телефоне — не открывать файл напрямую, а один раз выложить
папку куда-то, где она будет доступна по нормальной ссылке. Дальше сайт будет
одинаково открываться на любом телефоне и в любом браузере.
